# Conventions: Test Seams

Some methods and initialisers are `internal` (not `private`) specifically so tests can exercise them without going through real OS APIs. This is their inventory; [tests.md](tests.md) has the testing conventions around them. Add a new seam here.

- `HotkeyManager.handle(_:)` / `bindEventStream()` — interpretation and Combine binding seams, exercised by feeding synthetic `TapEvent`s
- `HotkeyManager(systemShortcuts:)` — macOS's own shortcut list injected, so availability tests need no `CopySymbolicHotKeys` read
- `HotkeyManager(resumeDeadline:)` — how long a resume waits for the tap's key-up before giving up, shortened so a test sees a silent tap release the shortcuts without waiting 10 s
- `InputMonitoringCapability.decode(_:)` — pure `CGEvent` → `TapEvent` decoder, `nonisolated` so the C tap callback can call it without crossing an actor boundary
- `InputMonitoringCapability.publishForTest(_:)` — pushes a synthetic `TapEvent` into the stream, bypassing the real tap (which requires an Input Monitoring grant on the running process)
- `InputMonitoringCapability.tapThread` — read-only, so `InputMonitoringLifecycleTests` can hold the tap thread and see it end once the capability is freed
- `RecordingIndicatorCoordinator.panel` — read-only, so `RecordingIndicatorCoordinatorTests` can check which real panel is up across a show and fade (planning 0030); the tests make each panel transparent so nothing flashes on screen
- `MicrophoneCapability.publishForTest(_:)` — pushes a synthetic `AVAudioPCMBuffer` into the stream, bypassing the capture unit
- `MicrophoneCapability.skipEngineForTesting` — flag that keeps `startEngine()` from opening a capture unit (the capability still marks itself listening, so `handleDeviceChange` counts). Required because the test runner usually *does* have Microphone permission, so without it the capture unit starts and silent audio races with `publishForTest` buffers (M4 got this for free because `tapCreate` returns nil without IM grant; mic capture has no natural skip)
- `MicrophoneCapability.handleDeviceChange()` / `deviceChangeCount` — the HAL device-change handler and a count of the changes it handled, so a test calls it directly and asserts it is live after `startEngine` and inert after `stopEngine` (planning 0032; warm-microphone spec)
- `MicrophoneCapability.noteDeviceChange()` — the listener block's entry point, which queues one handler run per burst of CoreAudio callbacks, so a test fires a burst and asserts a single run without a HAL property change
- `MicrophoneCapability.isListening` — whether the capability is between `startEngine` and `stopEngine`, so ready-mode tests see the unit kept running or stopped without a device (planning 0033)
- `MicrophoneCapability.setStatusForTesting(_:)` — drives `status` without the host's TCC read, so session tests pin whether the ready microphone opens or closes on the grant (mirrors `AccessibilityCapability.setStatusForTesting`)
- `InputMonitoringCapability.setStatusForTesting(_:)` — drives `status` without the host's TCC read, so session tests pin that the ready microphone waits for every permission, not only Microphone (planning 0033)
- `SystemAvailabilityMonitor.setForTesting(_:)` — drives the published sleep, lock and session state without a workspace notification
- `MicrophoneCapability.renderBuffer(format:frameCount:)` — the buffer the render callback hands to `AudioUnitRender`, with `frameLength` set so the HAL sees the slice's bytes; `MicrophoneRenderBufferTests` pins the byte size after the first on-device build delivered nothing
- `MicrophoneCapability.captureDevice` — read-only, the device the unit is pinned to
- `DictationStream(decode:)`, `finish(whenReady:)`, `settle()` and `trimSilence(_:)` — the stream takes its decode as a closure, so a fake decoder records every clip it hands the engine on every path (cut segments, the tail, a one-piece decode with streaming on or off or after a failed segment, and a kept recording through `transcribe(_:decode:)`); a fake wait records the clip a failed load would keep; `settle()` waits for the segments queued so far; the silence trim is tested on plain arrays; and an empty outcome names its reason (planning 0023, 0039)
- `AudioCaptureManager(makeResampler:)` — the converter for each format run; a test passes one that returns nil for a chosen format, so a run River can't convert is shown dropped and reported as `.conversionFailed` at release, with no unconvertible device (planning 0039)
- `AudioCaptureManager`'s injected `now` — the clock behind the capture-gap check (`captureGapExceeded`, `stopRecording`), with `watchdogInterval` for the mid-recording watchdog, so a 14 s recording with 1.5 s of audio is tested without recording for 14 s
- `WhisperKitModel.filterSpecialTokens(_:specialTokenBegin:)` — pure custom-dictionary prompt-token filter; tested on synthetic token lists so the load-bearing "drop everything `>=` `specialTokenBegin`" rule has a regression guard (a single mis-typed `<=` would silently corrupt decoding — `requirements/custom-dictionary.md`)
- `WhisperKitModel.resolveWithEmptyPromptRetry(promptTokens:decode:)` — the narrow decode seam (planning 0014): a closure. Takes an injected `(promptTokens:) async throws -> String` decode step, so the "a custom-dictionary prompt can only ever help" retry rule (prompted no-speech → unprompted retry; both empty or annotation-only → nil, nothing said, planning 0023 and 0039) is asserted without a live WhisperKit model. Production passes the real `decode`; tests pass a canned fake (`requirements/custom-dictionary.md`)
- `WhisperKitModel.isNonSpeechAnnotation(_:)` — pure whole-output classifier for Whisper's non-speech labels (`[BLANK_AUDIO]`, `(heavy breathing)`, …), which the pinned decode gates do not reliably suppress (probed on-device with real quiet-room/breath/keyboard clips — planning 0023). Annotation-only output becomes nil, nothing said, instead of pasted literal text; mixed annotation+speech output is never touched
- `ShortClip.padded(_:sampleRate:)` — the silence a clip under `Constants.shortClipSeconds` gets on each side before an engine decodes it (planning 0023), applied by each engine's adapter; tested on plain arrays
- `FluidAudioModel.spokenText(_:)` — FluidAudio's output as River reads it: trimmed, and nil when the model wrote nothing, so nothing said is tested without a model (planning 0039)
- `TranscriptionManager(modelName:store:)`, `ModelStore(downloadBase:loaders:)` and `FakeModelLoader` — the manager loads through a `ModelStore`, which holds each engine's `ModelLoader`, and tests pass a store with a fake that loads at once, fails the models in its `failing` set, and returns a `FakeModel` that transcribes any audio as its own name, or as the loader's `texts` give it ("" for no speech), so session tests reach typed text through the real decode path; it records each clip's length (`clipSeconds`), so they also see the clips River hands the engine. Session, manager and Settings snapshot tests run switches, retries and a model loading beside the one in use through it, with no download (planning 0037, [ADR 0001](../decisions/0001-defer-cycle-protocol-seams.md)). A model in its `held` set loads only at `finishLoad(of:)`, after `loadStarted(_:)` has seen it begin, and `report(_:of:)` / `report(progress:of:)` send what a real loader hears from its engine, during the load or late, after it; `holdsTranscriptions` holds each decode until `finishTranscriptions()`, and `mostTranscriptionsAtOnce` counts any overlap. So the tests drive a dictation through a real wait for the model (planning 0004)
- `TranscriptionManager.setModelLoadStateForTesting(_:)` — drives the in-use model's load state without a load, so a test sets the state a dictation meets; a wait that must end is driven through a held load instead. `openWaitCount` shows how many `waitUntilReady()` waits are open
- `WhisperKitLoader.downloadFolders(downloadBase:modelName:)`, `bytesOnDisk(in:)` and `downloadFraction(bytes:megabytes:)`, `FluidAudioLoader.downloadFraction(_:filesToDownload:)`, and `DownloadProgressThrottle(step:)` — each engine's download fraction as River reads it, tested on fixture folders and plain numbers with no download (planning 0004)
- `AppState.apply(modelSelection:)` — sets the Model section's state directly, so the Settings snapshot renders a switch (Waiting, failed) without loading a model
- `ModelStore(downloadBase:)`, `WhisperKitLoader.isModelCached(downloadBase:modelName:)` and `modelFolder(downloadBase:modelName:)`, each loader's `isDownloaded`, `folder(of:downloadBase:)` and `files(of:downloadBase:)`, and `ModelStore.diskUsage(of:)` — the store takes the download base once, and the downloaded check, `TranscriptionManager.deleteModel(named:)` and its refusals, and the measured sizes all read it, so tests write a fixture model folder in a temporary directory and never touch the user's models (planning 0038). `FluidAudioLoader.models` is internal so a test checks every FluidAudio model in the catalogue against it
- `ModelSectionView(hoveredRow:)` — shows a row's ⋯ as the pointer would, so the Settings snapshot draws it
- `RiverSession.wireHotkeyCallbacks()` — wires `onActivate`/`onDeactivate` without starting the tap, so the chain can be tested end-to-end via `publishForTest`
- `RiverSession.handleActivate()` (sync) / `handleDeactivate()` (async) — state-guarded transitions; tests `await` `handleDeactivate` directly to drive the full `.recording → .processing → .idle` cycle on the test's own timeline, rather than waiting for the Task-wrapped callback the production wiring uses
- `TextInsertionManager.chunk(_:maxUnits:)` — the pure, grapheme-safe splitter for keystroke injection (planning 0011), whose last two chunks share their characters within the unit budget (planning 0031); unit-tested for the unit budget, surrogate-pair safety and the last chunk over lengths 2 to 100. The `CGEvent.post` leaf stays untestable in CI; manager tests assert the down+up-per-chunk count via `AccessibilityCapability.postedEventCountForTesting`
- `AccessibilityCapability.skipPostForTesting` — flag that short-circuits the real `CGEvent.post`. Required because the test runner's trustedness leaks into the test process, so without it `postKeyEvent` would fire a real paste into whatever app was focused at test time (mirrors `MicrophoneCapability.skipEngineForTesting`)
- `AccessibilityCapability.setStatusForTesting(_:)` — drives `status` synchronously, bypassing `recheck()`'s non-deterministic host TCC read, so a test can lock the `postKeyEvent` gate open or closed
- `AccessibilityCapability.postedEventCountForTesting` — counts the posts that `skipPostForTesting` suppressed, so manager tests assert the capability was asked to post the expected number of events without a real `CGEvent.post`
- `AccessibilityCapability.postedKeyDownTextForTesting`, `TextInsertionManager`'s injected `pause`, and `RiverSession.copyLastTranscript(to:)` — the text each suppressed key-down would have typed, the gaps between chunks without sleeping, and a private pasteboard, so tests check that every character is typed in order, that chunks are spaced out, and that the typed text equals the copied text without touching the user's clipboard (planning 0031). A pause that yields lets two deliveries run at once, so a test sees that the second waits its turn, and a pause held open lets two more queue behind the first, so a test sees them keep their order (planning 0039), or starts a dictation while a Paste last waits or types (`RiverSessionTests`' `InsertionPause`)
- `AccessibilityCapability.trustReadForTesting` — replaces the `AXIsProcessTrusted()` read inside `recheck()`, so tests pin that status is exactly the OS trust read and nothing else can downgrade it
- `AccessibilityCapability.classifyFocusedTarget(role:subrole:)` — the pure editable-role table behind the paste guard (planning 0001), tested against a role table (editable / non-editable / unknown-fails-open) with no AX grant; the focused-element read leaf stays untestable in CI
- `AccessibilityCapability.focusedTargetForTesting` — pins the focused-target classification so manager tests never reach the real AX read (the host's live focus at test time would leak into the classification); mirrors `skipPostForTesting`
- `*Capability.map(...)` — the pure status-mapping functions, internal so tests pin the granted/denied/unknown mapping without a real TCC grant
- `RiverSession.configurationApplyCount` / `configurationDeferCount` — internal counters so tests can assert subscription wiring without reaching into the handler closures
- `AppState.apply(...)` — the update entry points (`RiverState`, `RiverError`, `notice:`, `modelLoadState:`, `inputLevel:`, `hasLastTranscript:`, `liveTranscript:`, `isLiveTextShown:`, `dictationEvent:`, `downloadProgress:`, `keptRecordingCount:`), internal so tests drive observation, the redaction-at-the-boundary choke point, and the floating stack (`apply(liveTranscript:)` shows the transcript) without standing up SwiftUI or a live session
- `MenuBarPresentation.visual(state:hasError:modelLoadState:fraction:)` — pure `state` + error + load state → icon/label mapping, exercised directly so the [core-feature.md](../requirements/core-feature.md) item 5 icon/label contract has a regression guard without a real `MenuBarExtra`. The cycle states return a glyph asset name, which is also the bundle's filename contract (`make verify` asserts those files ship)
- `KawaIndicatorVoice(makeEngine:)` — the live panel's feed (a level reading in, the frame's engine out: loudness, a fresh engine per cycle, the advance, the ripple log), seeded by tests; the snapshot harness draws through it and `KawaMarkPanelFace`, so a held frame is fed and drawn the way the app does it
- `GlassRenderer.arguments(...)` / `packed(_:)` — the Glass shader's interface as named values, tested against `KawaGlass.metal`'s own signature without a GPU, so a swapped or missing argument fails a test instead of rendering wrong
- `MenuBarGlyphImages.withDot(_:muted:)` — the runtime drawing of Listening and Transcribing (the red dot, the muted one), rendered under each appearance so the dot's colors and the mark's are checked without a menu bar
- `MenuBarRingImages.icon(for:)` / `statusGlyph(for:dark:)` — the menu bar's runtime ring, rendered in tests to check it is a template at both screen scales, grows with the download, and turns akane only beside the menu's status line
- `ModifierKey` — the pure modifier-key table and its down-or-up rule, tested so a dropped key, Caps Lock or fn coming back as a lone key, or a side misread from the device bits is a failing test, not silent drift (mirrors `MenuBarPresentation`)
- `HotKeyRegistry(calls:)` / `publishForTest(_:)` — the Carbon register, unregister and handler calls are injected (`.inert` accepts everything), so tests check typed refusals and drive hot key presses and releases without registering a real hot key; mirrors `InputMonitoringCapability.publishForTest`
- `ShortcutRecorderModel(row:hooks:)`, `handle(_:)` and `ShortcutRecorderHooks` — the row it records for, one key event as the window's monitor delivers it, and the session's reach (pause, resume, check, save) as closures, so tests and the Settings snapshots drive the recorder with no key press and no session
- `ShortcutText`'s injected `character` — what a key types on the keyboard layout, replaced by the US layout so tests read the same on any Mac
- `SystemShortcuts.entries(from:)` — the pure read of `CopySymbolicHotKeys`' dictionaries
- `AppState.apply(shortcutRegistrations:)` — drives a failing shortcut's badge and line without another app holding it
- `AppState(schedule:)` — the `TimerScheduler` behind the status's reveal and holds, which tests capture and fire by hand (`ManualScheduler`), so the 0.90 s hand-off, the 4 s hold and Ready's hold are tested without waiting
- `StatusRing.frame(at:events:reduceMotion:)`, `StatusRingEvents.record(fraction:at:)`, `StatusRingCycle.next(...)` and `StatusRowWords.of(...)` — the status ring and its words as pure values, so each moment of the ring's spec is a test (planning 0004)
- `TextInsertionManager`'s injected `frontmostApp` — the app in front, as a process ID a test moves, read before each chunk, so held text, a switch mid-insert included, is tested without switching apps; `RiverSession.currentKeptRecordingCount` counts the recordings a failed load kept
- `RiverIndicatorView(appState:markCycle:shown:statusRing:)` and `StatusRow(…ring:)` — a status and a ring already under way, handed in so the snapshot harness draws the status in the mark's place at one moment
- `HotkeyManager(pasteTimeout:)` — how long Paste last waits for the tap's key-up, shortened so a test sees a silent tap paste anyway
- `TranscriptionManager.evaluateDictionaryPrompt(wavPath:)` — internal seam, which needs a loaded Whisper model, for the **A/B eval harness** (`DictionaryEvalTests`): decodes one fixed clip with and without the dictionary prompt, bypassing the empty-fallback, so a recorded clip shows whether the prompt biases or degenerates. The harness is **env-gated** (`.enabled(if: RIVER_AB_WAV)`) so the normal suite skips it; it loads the real model and writes its result to `ab-result.txt`. Used to confirm `small.en` biases where `base.en` empties (`requirements/custom-dictionary.md`)
- `WhisperKitLoader.loadAudioSamples(fromPath:)` — internal seam for the **transcription eval harness** (`TranscriptionEvalTests`, planning 0022): wraps WhisperKit's `AudioProcessor.loadAudioAsFloatArray` so WhisperKit stays a single import boundary and the test target need not depend on it. Not used in production (live capture supplies samples directly)

Mark them clearly:

```swift
// internal for testability (CGEventTap cannot be created in CI)
func decodeFlagsChanged(_ event: CGEvent) -> ActivationEdge? { ... }
```

**Do not promote these to `public`.** Internal is enough; public is an API contract.
